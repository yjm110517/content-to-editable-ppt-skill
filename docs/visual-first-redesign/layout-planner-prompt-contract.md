# 1. 文档目的

本文档不编写最终 `planner.md` 提示词全文，而是冻结布局规划代理的稳定任务合同：职责、输入类别、Authority、初次规划与定向修订、统一重建计划，以及必须停止的情形。后续正式 Prompt、Schema、调用包和 Runtime 适配必须遵守本合同。

---

# 2. 角色定位

布局规划代理是 Stage 3 中负责**页面视觉对齐与重建规划**的专业代理。它面对的不是一张未知页面图片；在进入 Stage 3 时，系统已掌握 Stage 1 已确认的正式内容、语义对象与关系、图表 / 表格结构化数据、Stage 2 需要独立重建的重要视觉对象，以及用户确认后的最终设计图。

它的核心任务不是从图片重新发现页面内容，而是：

> **把已知对象对应到最终设计图中的视觉实现，并决定这些对象如何重建为可编辑 PowerPoint。**

---

# 3. 两个逻辑任务

```text
已知对象 + 最终设计图
        ↓
任务 1：视觉位置对齐
        ↓
任务 2：重建方式决策
        ↓
统一重建计划
```

两个任务属于同一个布局规划代理；v1 默认一次代理调用完成，不创建独立的视觉定位代理或重建代理。是否未来拆分，只能由 Benchmark 证据决定。

---

# 4. 职责边界

布局规划代理不得：

- 重写正式文案、数字、单位、专名或结论；
- OCR 最终设计图并覆盖 Stage 1 内容或数据；
- 重新规划 Storyline、流程、层级或连接关系；
- 为了重建方便而重新设计页面；
- 将正式文字整体栅格化，或将图表 / 表格截图代替原生对象；
- 把整页设计图作为整页背景交付，或在 Stage 3 再次调用图片生成模型；
- 审核自己的最终视觉结果，或直接执行 PPT 构建、渲染、结构 QA、打包。

> **布局规划代理只做视觉理解与重建决策，不做内容创作、最终构建或独立审核。**

---

# 5. 输入合同

本合同冻结输入信息类别，不冻结具体文件名；实现可将它们组织成 JSON、Markdown 或图像文件。

| 输入 | 必须提供的信息 | Authority |
|---|---|---|
| 用户确认后的最终设计图 | 构图、位置、比例、留白、层级、重叠、颜色、字体视觉、阴影与复杂视觉效果 | 最终视觉标准，但非唯一来源 |
| Stage 1 正式内容 | 标题、正文、标签、数字、单位、专名、结论及其他正式文字 | 正式内容权威 |
| Stage 1 语义结构 | 稳定对象编号、页面区域、对象角色、阅读顺序、流程 / 层级 / 连接关系 | 语义关系权威 |
| Stage 1 结构化数据 | 原生图表 / 表格的正式数据 | 数据权威 |
| Stage 2 重要视觉对象 | 需独立裁切、摆放、缩放、层级控制或重要重叠的对象编号 | 补充纯视觉对象 |
| 重建规则 | Native、SVG、Raster 的对象重建策略 | 重建方式边界 |
| 输出约束 | 统一重建计划允许表达的信息 | 输出边界 |

Stage 2 不必为每个小装饰编号；但大型 3D 人物、产品图、重要光晕等需要独立处理或会影响层级的视觉对象，应具有稳定编号。低影响的小装饰允许有限补充识别，不得借此重新解释整页语义结构。

## 5.1 Authority 与冲突

| 冲突项 | 处理 |
|---|---|
| 最终设计图文字与 Stage 1 不同 | 使用 Stage 1 正式文字 |
| 最终设计图图表数字与 Stage 1 不同 | 使用 Stage 1 结构化数据 |
| 线稿与最终设计图的位置略有变化、语义未变 | 保留 Stage 1 结构，位置参考最终设计图 |
| 最终设计图改变真实流程或层级关系 | `authority_conflict` → BLOCK |

# 6. 工作模式一：初次规划

初次规划的输入为 Stage 1 内容、语义结构、结构化数据，Stage 2 重要视觉对象，最终设计图与重建规则；输出为一份统一重建计划。

## 6.1 验证与视觉位置对齐

首先确认所有必需语义对象都进入当前规划范围；不得因为图片难以看清而静默忽略。

对每个对象判断：页面区域、近似宽高比例、相对位置、主次比例、前后层级、重要重叠关系与必要视觉分组。不得重新猜测 Stage 1 已确认的流程、层级与连接关系。

## 6.2 几何精度原则

布局规划代理**不承担像素级复刻任务**。目标是：

> **给出足以完成首轮 PPT 构建的近似可执行几何。**

必须保证：

- 页面区域、视觉重心和主次比例基本正确；
- 前后层级和重要重叠关系正确；
- 不出现明显构图错误。

允许小幅位置、宽高或卡片间距差异，也允许用户在 PowerPoint 中进一步微调。

不允许左右区域完全反转、主视觉比例严重错误、前后层级错误、重要对象错误遮挡，或流程顺序在视觉上被破坏。

## 6.3 坐标表达

本合同不冻结最终坐标字段。实现可以使用页面归一化比例、图片像素坐标或其他可确定性转换的形式；不要求代理进行 PowerPoint 英寸换算。

> **优先目标是稳定表达近似可执行几何，而不是测量像素。**

## 6.4 重建方式决策

```text
正式文字 → PowerPoint 原生文字
基础卡片 / 形状 → PowerPoint 原生形状
连接线 / 箭头 → PowerPoint 原生连接线
可恢复平面矢量 → 原生形状 / SVG
图表 → PowerPoint 原生图表
表格 → PowerPoint 原生表格
复杂插画 / 照片 / 3D / 纹理 → 从最终设计图安全裁切
```

# 7. 工作模式二：定向修订

只有在首轮 PPT 已构建、结构 / 可编辑性 QA 通过、视觉审核代理给出 `REVISION_REQUIRED` 后，宿主代理才发起定向修订。输入至少包括：上一版统一重建计划、最终设计图、当前渲染图、问题对象与类型、允许修改范围，以及默认锁定的已通过对象。

若审核仅指出 `chart_01`，不得顺手修改标题、流程或主视觉；若需扩大范围，必须给出可追溯理由。

| 修订范围 | 适用情形 |
|---|---|
| 单对象 | 位置、尺寸、裁切或单个图表比例明显不对 |
| 局部分组 | 卡片与连接线、人物与卡片遮挡、局部布局失衡 |
| 整页重新规划 | 整体构图失败、大量对象错误且无法局部修复；仅为最后手段 |

任何修订均必须重新经过确定性编译、PPT 构建、结构 / 可编辑性 QA 与视觉审核。最大修订次数由后续 Runtime 冻结。

---

# 8. 统一重建计划

代理只维护**一份统一重建计划**，而不直接维护历史 Runtime 的 `layout.json`、`crops.json`、`asset_manifest.json` 等多份交叉文件。确定性转换程序负责从该计划生成它们，使同一对象的事实只由代理描述一次。

最终 Schema、字段和文件名尚未冻结；最小语义必须能够表达：

```text
页面身份、对象编号、对象来源、对象角色、内容引用、数据引用、
视觉区域、近似尺寸、层级、重要重叠、对象重建方式、资产来源、
裁切要求、必要样式提示、修订锁定状态
```

概念示例：

```yaml
elements:
  - id: title
    content_ref: title
    visual_region: { x: 0.07, y: 0.06, width: 0.40, height: 0.10 }
    representation: { type: native_text }
  - id: chart_01
    data_ref: chart_01_data
    visual_region: { x: 0.08, y: 0.58, width: 0.40, height: 0.28 }
    representation: { type: native_chart }
  - id: hero_illustration
    visual_region: { x: 0.66, y: 0.18, width: 0.28, height: 0.62, z_index: 20 }
    representation: { type: raster_asset, source: approved_design, crop_required: true }
```

这些数值只表达近似首轮几何，不代表像素级恢复要求。

---

# 9. 复杂视觉、图表与表格

复杂视觉只能从用户确认后的最终设计图中安全裁切。若包含正式文字、必须原生的图表 / 表格、不可独立的语义对象，或会产生不可接受的背景接缝，则为 `unsafe_crop` → BLOCK；Stage 3 不重新生图绕过问题。

正式图表必须规划为原生 PowerPoint 图表，正式表格必须规划为原生 PowerPoint 表格；不得截图或用大量 Shape 模拟主体。缺少正式数据为 `missing_structured_data` → BLOCK。

---

# 10. 失败与阻断规则

布局规划代理必须被允许停止，不能为了“总要给一个答案”而继续猜测。

| 类型 | 含义 | 处理 |
|---|---|---|
| `grounding_incomplete` | Stage 1 必需对象无法可靠完成视觉位置对齐 | BLOCK / Review |
| `authority_conflict` | 上游语义与设计图存在无法按 Authority 解决的结构冲突 | BLOCK，返回上游确认 |
| `missing_structured_data` | 原生图表 / 表格所需正式数据缺失 | BLOCK，返回 Stage 1 |
| `unsafe_crop` | 复杂视觉不能安全独立裁切 | BLOCK，返回 Stage 2 |
| `unsupported_reconstruction` | 现有策略无法同时满足编辑性和合理视觉表现 | BLOCK，返回 Stage 2 |

---

# 11. 与视觉审核代理的接口

布局规划代理不负责最终视觉审核。视觉审核代理独立运行，可给出：

```text
PASS
PASS_WITH_MINOR_DIFFERENCES
REVISION_REQUIRED
BLOCK
```

`PASS` 与 `PASS_WITH_MINOR_DIFFERENCES` 不修订；后者允许轻微位置、间距、阴影、圆角或原生图表渲染差异。只有 `REVISION_REQUIRED` 进入定向修订；`BLOCK` 返回相应上游阶段。

---

# 12. 成功标准

成功不等于与最终设计图逐像素一致。成功应满足：所有必需语义对象已处理，正式内容和数据未被修改，主要区域、构图、对象比例、层级与重要重叠关系基本正确，重建方式符合编辑性政策，复杂视觉可安全恢复，输出可被确定性程序执行，且用户只需可选微调而非先修正明显错误。

---

# 13. v1 不冻结的事项

本合同不冻结：完整 Prompt、Few-shot 示例、最终模型选择、Context 与统一重建计划文件名、最终 JSON Schema、坐标字段形式、最大修订次数、Reviewer 数值阈值、裁切算法与具体 PPT Builder / 后端组合。

---

# 14. 冻结决策摘要

| 项目 | v1 决策 |
|---|---|
| 代理职责 | 已知对象视觉位置对齐 + 重建方式决策 |
| Agent 数量 | 两个逻辑任务由一个布局规划代理完成 |
| 正式内容、数据、语义关系 | Stage 1 为权威 |
| 最终视觉 | 用户确认后的最终设计图为视觉标准 |
| 几何精度 | 首轮可执行的大致位置 / 比例，不追求像素级复刻 |
| 输出 | 一个统一重建计划 |
| 初次规划与修订 | 同一代理完整规划；定向修订默认锁定已通过对象 |
| 复杂视觉 | 安全裁切，不重新生图 |
| 图表 / 表格 | 原生 PowerPoint 对象 |
| 不确定信息 | 允许 BLOCK，禁止硬猜 |
| 最终视觉审核 | 独立视觉审核代理负责 |

# 15. 最终工作流

```text
Stage 1 已确认内容 / 结构 / 数据
+ Stage 2 重要视觉对象
+ 用户确认最终设计图
        ↓
布局规划代理：初次规划
        ├─ 视觉位置对齐
        └─ 重建方式决策
        ↓
统一重建计划
        ↓
确定性校验 / 转换 → PPT 构建 → 结构 / 可编辑性 QA
        ↓
视觉审核代理
        ├─ PASS / PASS_WITH_MINOR_DIFFERENCES → Accepted
        ├─ REVISION_REQUIRED → 布局规划代理定向修订 → 重新构建与审核
        └─ BLOCK → 返回 Stage 1 / Stage 2
```

---

# 16. 结论

布局规划代理不是从图片重新理解全部页面的通用视觉 Agent。它是在已知内容、语义结构和重要视觉对象基础上，参考用户确认的最终设计图，给出足以完成首轮可编辑 PowerPoint 构建的近似视觉几何和对象重建决策；局部问题只进行有界修订，信息不足或规则冲突则明确阻断。
