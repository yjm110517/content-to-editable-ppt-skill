# 阶段 4：核心验证与文档收口

## 文档状态

- 状态：依赖阶段 3
- 前置文档：[阶段 3：删除旧体系并缩减安装包](03-legacy-removal.md)
- 总计划：[Content to Editable PPT Skill 精简计划](../skill-simplification-plan.md)

本阶段只是仓库改造批次，不是 Skill Runtime 阶段或用户状态。

本阶段证明精简后的 Skill 仍能完成用户任务，并把 README、`SKILL.md` 和当前实现统一起来。本阶段不恢复旧 P 阶段，不启动完整视觉布局重构。

## 目标

1. 建立保护当前产品风险的最小核心测试集；
2. 完成一套真实小型多页 Deck 端到端验证；
3. 验证独立单页兼容入口及完整审核交付流程；
4. 清除旧 P 阶段文档的当前权威地位；
5. 记录精简前后规模和测试耗时；
6. 确认 Smoke、Fixture 和历史 Evidence 无法进入正式结果；
7. 宣布第一目标“正式 Skill 瘦身”完成或列出阻断项。

## 前置条件

- ADR-043 的 `scripts/run.py` 多页主入口已生效，独立单页兼容入口保持有效；
- 旧外部入口已删除；
- 安装包内旧阶段脚本、Schema 和 Reference 已清理；
- Agent 配置已按决定处理；
- 仓库级历史资料已完成计划内清理；
- 阶段 3 已提供精简后文件统计和验证命令。

## 核心测试范围

核心测试只覆盖当前用户产品风险。

### 必须覆盖

- 用户材料中的正式内容没有丢失；
- 页面顺序和标题正确；
- 文字没有溢出；
- 元素没有越界；
- 标题、正文和主要结构为原生可编辑对象；
- PPTX 可以打开、保存和重新渲染；
- 多页主入口不读取 `tests/`、`baseline/`、`reports/`、阶段工具或 `work/field-validation/`；
- Smoke、Rejected Preview 和固定 Evidence 不会成为正式输出；
- 独立单页兼容入口、Planner、Reviewer、Recovery、Review Gate 和正常交付仍可用。

### 不在第一目标中新增

- 完整文字安全区和视觉占用边界算法；
- 新版图文相交检测；
- 新视觉 Reviewer；
- 三套 Field Validation；
- 像素级 Golden；
- 字节级 ZIP 确定性；
- 多层 Evidence Hash 闭包。

图文相交结构性修复属于总计划中的第二目标，瘦身完成后单独实施。

## 测试精简方法

### 1. 建立风险映射

为每个保留测试说明它保护的用户风险。记录在测试名称、简短注释或提交说明中，不新增测试注册数据库。

如果两个测试保护相同风险且输入差异没有用户价值，应合并或删除重复项。

### 2. 建立最小 Fixture

至少保留：

- 一套内容转多页 PPT 的小型真实 Fixture；
- 独立单页兼容入口的现有核心回归和必要 Fixture。

Fixture 应小、可读、无真实敏感信息，不依赖 D03/D05/D08 历史 Evidence。

### 3. 约束测试输出

所有测试使用临时目录。测试结束后不得在用户 `work/`、`reports/` 或安装包中留下输出。

### 4. 记录耗时

运行核心测试并记录：

- 总耗时；
- PowerPoint 相关测试耗时；
- 是否适合本地持续运行；
- 哪些测试只在 Windows + PowerPoint 环境运行。

耗时预算以实际基线制定，不用测试数量作为通过门槛。

## 真实 Deck 验证

使用一份小型、非历史 Fixture 的真实材料，至少生成 3 页：

1. 标题或概览页；
2. 正文或结构页；
3. 总结页。

验证：

- 用户材料与输出内容对应；
- 页面顺序正确；
- 原生文字存在；
- 主要形状或图表可编辑；
- PPTX 能被 PowerPoint 打开和保存；
- 所有页面可以渲染；
- 预览与最终 PPTX 对应；
- 最终输出目录只包含约定交付物；内部工作文件只能进入独立工作目录或临时目录；
- 日志没有读取非生产目录。

该验证不创建新的 Field Validation Gate 或 Evidence Package。

## 文档收口

### README

README 只保留当前有效内容：

- 项目用途；
- 安装环境；
- 用户可以提供什么；
- 一次方案确认；
- 多页主入口、独立单页兼容入口及 Skill 调用方法；
- 多页主路径默认交付结果和独立单页七文件交付说明；
- 核心限制和常见失败。

删除：

- P0～P5 当前状态表；
- D03/D05/D08 Gate 说明；
- 阶段评估器命令；
- Live Evidence 和不可变打包细节；
- 历史版本权威层级。

### `SKILL.md`

复核 `SKILL.md` 只描述：

- 任务识别；
- 材料读取；
- 一次合并方案；
- 用户确认；
- 多页主入口和独立单页兼容入口；
- 核心编辑性规则；
- 失败停止条件；
- 多页主路径的 PPTX 和预览交付，以及独立单页的现有七文件交付。

### 历史文档

旧 Architecture、Specification、Contract、Testing 和 P 阶段 Plan 不再作为当前权威。按照阶段 3 的清理决定：

- 删除已经没有当前价值的文件；
- 对确需保留的少量历史决策明确标为历史；
- 不再为旧文档创建新版本；
- 不创建新的归档目录。

### 当前权威

精简完成后，当前权威应收敛到：

1. `SKILL.md`：用户和宿主执行规则；
2. README：产品、安装和使用说明；
3. 精简 ADR：架构决策；
4. 本总计划及四份实施文档：精简过程依据，完成后转为历史执行记录；
5. 少量仍有效的构建和质量 Reference。

## 最终验证命令

根据最终入口补充准确命令，至少包括：

```powershell
python content-to-editable-ppt/scripts/verify_install.py
python -m unittest <core-test-modules> -v
python content-to-editable-ppt/scripts/run.py <real-deck-arguments>
git diff --check
git status --short
```

还必须使用 Microsoft PowerPoint 实际打开、保存和渲染最终 PPTX。

占位命令 `<core-test-modules>` 和 `<real-deck-arguments>` 必须在阶段完成前替换，不能保留在最终 README 或 `SKILL.md` 中。

## 验收清单

### 用户路径

- [ ] 用户只需提供材料、确认方案、接收结果；
- [ ] 用户侧不出现 P0～P5；
- [ ] 只有一个可发现生产入口；
- [ ] README 和 `SKILL.md` 不要求操作 State、Manifest、Gate 或 Evidence；
- [ ] 多页主路径默认交付为 PPTX 和预览，独立单页仍按现有七文件契约交付。

### 运行能力

- [ ] 安装验证通过；
- [ ] 真实小型多页 Deck 通过；
- [ ] PPTX 可打开、保存和重新渲染；
- [ ] 正式内容完整；
- [ ] 主要内容可编辑；
- [ ] 独立单页兼容入口的现有核心回归通过。

- [ ] 没有通用旧兼容层；

- [ ] 没有新的精简状态机、Gate 或 Evidence；
- [ ] README、`SKILL.md`、ADR 和代码一致；
- [ ] `git diff --check` 通过。

## 阶段完成结论

完成后必须明确给出两种结论之一：

- `正式 Skill 瘦身完成`：所有第一目标验收项通过；
- `正式 Skill 瘦身未完成`：列出具体阻断项和所属文件，不用新增阶段或状态表达。

## 回退

如果核心运行能力失败，回退阶段 3 中对应的删除功能簇；如果只是文档错误，独立修订文档。不得恢复旧 P 阶段为默认用户流程。

## 后续质量工作

第一目标完成后，另行执行总计划的第二目标：

- 明确文字安全区；
- 限制生成视觉区域；

这些工作应扩展精简后的 Deck Plan 和多页主入口，不得修改独立单页兼容行为，也不得恢复旧 P3.2、P3.3、P4 用户阶段。
