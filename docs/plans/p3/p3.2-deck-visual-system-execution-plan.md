# P3.2 Deck Visual System 与 Prompt Contract 执行计划

## 状态与目标

P3.2 建立让 P3.3 稳定设计整套 Deck 的视觉语言、文字空间约束、图层责任和确定性生成上下文。本阶段不生成图片、Design Preview、Contact Sheet 或 PowerPoint，也不评价视觉质量。

```text
P1 / P2 / P3.1 Authority
→ Host Deck Visual System Pass
→ Hard Constraints + Soft Design Guidance
→ Text Footprint Compilation
→ Deterministic Prompt Compilation
→ Style Anchor Request
→ P3.2 Contract / Prompt Gate
```

## 核心契约

- Hard Constraints 只负责字体、色彩、比例、安全区、Text Footprint、Authority、图层责任和禁止项。
- Soft Design Guidance 只提供 Grid、Template、Card、图片、构图和视觉节奏建议；不得固化页面 BBox 或把 P3.3 退化为模板化 PPT。
- Text Footprint 使用实际 P1 文字、实际字体文件 Hash、Pillow 10.4.0 和 96 DPI 确定性计算最小空间，不固定最终位置。
- Prompt Package 明确 Generated Visual Layer 不是 Final/Approved Design Preview。用户只能确认经 Deterministic Compositor 注入正式文字、Resolved SVG 和 Chart Preview 后的 Final Design Preview。
- Raster Handoff 元素必须空间隔离、无文字、无遮挡、保留安全边距，并避免背景融合和长距离阴影。
- 主 Style Anchor 按代表性选择；复杂异常页进入 High Risk 列表，不自动成为 Anchor。

## 调用与 Gate

```text
Initial Host Pass = 1
Contract Correction <= 1
Host Model Invocations <= 2
Prompt Compiler Agent Calls = 0
Image / Planner / Reviewer / PowerPoint Calls = 0
```

P3.2 Gate 只证明 Authority、Contract、Text Footprint、Prompt、Cache 和状态正确，必须记录 `visual_quality_status = not_evaluated`。实际 Style Anchor 和视觉质量证据属于 P3.3。

## PR 顺序

1. `codex/p3-visual-system-contracts`：Authority、Hard/Soft Contracts、Icon Index、State。
2. `codex/p3-text-footprint-prompt-compiler`：Footprint、Element Intent、Prompt Compiler、Cache、CLI。
3. `codex/p3-visual-system-contract-gate`：D03/D05/D08、Host Smoke、Gate Report 和 Skill 状态。

每个 PR 必须从最新 `main` 创建，完成确定性测试、审核、Merge Commit 和 Post-Merge Verify 后再进入下一项。
